# Widget 参数定义、可视化配置器与首页

## 概述

为 Silent Widgets 增加可视化配置器，并将参数定义、widget 本体和页面环境分开。用户可在配置器中连续修改参数、查看预览并复制用于 Notion 的嵌入地址。

每个 widget 在 `app/widgets/<name>/config.ts` 中定义参数及参数值规则。独立展示页和配置器使用同一套规则。父页面决定渲染区域的尺寸，widget 本体填满区域并响应参数变化。配置器直接挂载 widget 组件。

首页采用接近 Notion 文档页的工具目录设计，只展示静态信息。现有 `app/pages/index/page.vue` 是配置器布局参考，实施时先迁移这份布局，再替换首页。

本轮覆盖五个现有 widget：

| 标识              | 中文名称 | 说明                               |
| ----------------- | -------- | ---------------------------------- |
| `year-progress`   | 一年进度 | 查看今年已经过去多少               |
| `mini-calendar`   | 迷你日历 | 用紧凑的点阵查看本月日期           |
| `date-counter`    | 日期计数 | 查看距离某一天还有或已经过了多少天 |
| `daytime-meter`   | 一天进度 | 用圆环显示一天的时间进度           |
| `repo-stargazers` | 仓库星标 | 显示 GitHub 仓库的 Star 数量       |

| 模块                  | 职责                                                  |
| --------------------- | ----------------------------------------------------- |
| widget 的 `config.ts` | 导出参数定义、特殊值规则和展示信息                    |
| widget 本体           | 渲染内容，维护自身数据、局部样式和 i18n，响应参数变化 |
| 独立展示页            | 读取 URL，加载 widget，设置标题和 SEO，提供全屏区域   |
| 配置器页面            | 编辑参数，显示校验提示，提供预览区域，生成和复制地址  |
| 首页                  | 陈列静态工具目录，提供配置入口和 Notion 嵌入说明      |
| 公共参数工具          | 解析、校验、应用默认值、序列化以及类型推导            |

不增加共用 widget 容器组件。背景、CSS 变量和 widget 语言环境归入 widget 本体；可以复用纯函数和 composable。父页面保留普通布局元素，并决定可用宽高。

配置器使用直接组件预览，不使用 iframe 预览或跨窗口消息。widget 独立页面仍可供 Notion 通过 iframe 嵌入。

说明文字与参数规则共同保存在 `config.ts`，暂不分离。依赖方向应保证 widget 不导入配置器 UI。配置器和 widget 仍处于同一工程，不承诺无关页面的构建哈希永远不变。

本轮新增界面采用简体中文文案，名称旁可保留英文名称。widget 继续保留现有 `en-US`、`zh-CN` 和自动语言选择能力。界面跟随系统明暗模式。

#### 4. 参数定义与值流转

每个 `config.ts` 导出 `params` 和 `meta`。参数定义采用对象键作为参数名。下面展示迷你日历的 `weekstart` 条目：

```ts
export const params = {
  weekstart: {
    type: 'integer',
    default: 0,
    label: '每周起始日',
    description: '选择日历每一周从哪一天开始。',
    options: [
      { value: 0, label: '星期日' },
      { value: 1, label: '星期一' },
      { value: 2, label: '星期二' },
      { value: 3, label: '星期三' },
      { value: 4, label: '星期四' },
      { value: 5, label: '星期五' },
      { value: 6, label: '星期六' },
    ],
  },
} as const satisfies Record<string, WidgetParam>
```

不要用 `const params: Record<string, WidgetParam>` 擦除具体键名。`WidgetParam` 按类型组成联合类型，并约束默认值、解析结果及序列化输入之间的关系。类型从定义推导，不增加生成 `.d.ts` 文件的步骤。[TypeScript 的 satisfies 说明](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-4-9.html#the-satisfies-operator)

字段约定：

| 字段                   | 用途                                                       |
| ---------------------- | ---------------------------------------------------------- |
| `type`                 | 选择值类型及默认控件：文本、日期、整数、布尔值、颜色、语言 |
| `default`              | 参数缺失时的默认值；值类型应与参数类型一致                 |
| `label`、`description` | 控件标签和参数说明                                         |
| `required`             | 生成有效嵌入地址前，参数是否应具有非空有效值               |
| `options`              | 枚举值及显示名称，例如一周的七天                           |
| `darkVariant`          | 颜色是否允许分别设置浅色和深色值                           |
| `parse`、`serialize`   | 按需提供特殊转换；普通参数使用公共实现                     |

`required` 表示配置校验规则，不直接等同于 Vue 的必传 prop。日期和仓库参数仍可具有空字符串初始值，此时 widget 显示缺失参数状态，配置器禁止复制尚不可用的地址。

公共参数工具接受原始查询字符串，返回规范化参数和逐字段问题。原始值应保留“缺失”与“存在但为空”的区别。重复查询键延续当前行为，使用最后一个值。未声明的键不进入 widget props，也不进入生成地址。

解析与表单共用同一条值链路：

```text
查询字符串 / 表单草稿
          ↓
参数定义：转换、校验、默认值
          ↓
规范化参数 + 字段问题
          ↓                  ↓
widget props             配置器提示
          ↓
序列化为独立展示地址
```

公共工具集中应用默认值，避免 `config.ts`、页面和组件各自维护一份值。Vue 的运行时 props 声明由同一份定义派生；不要依赖 Vue 编译器解析整个复杂条件类型。适配函数应保留返回值的类型信息。[Vue props 类型限制](https://vuejs.org/api/sfc-script-setup.html#type-only-props-emit-declarations)

常见值规则如下：

| 参数类别 | 规则                                                                                |
| -------- | ----------------------------------------------------------------------------------- |
| 文本     | 保留显式空字符串；不把空值转换为布尔值                                              |
| 布尔值   | 保留 `?humanize`、`?humanize=`、`?humanize=true` 为真；`false` 为假；其他值报告问题 |
| 整数     | 只接受有效整数；`weekstart` 限制为 0 到 6；缺失时为 0                               |
| 颜色     | 保留单色与浅色、深色双值协议；单色同时用于两种模式；支持现有透明度值                |
| 日期     | 保留字符串输入和当前日期解释规则；本轮不重定义时区或计数算法；非空值应可解析为日期  |
| 仓库     | 接受 `owner/name`；缺失或结构不完整时不请求 GitHub                                  |
| 语言     | 提供自动、简体中文和 English；自动状态序列化为省略 `lang`                           |

颜色解析只规范化颜色值的组合结构，不实现完整 CSS 语法验证器。分隔双值时区分括号内的逗号，保留颜色原文；浏览器可提供辅助输入提示，但服务端与客户端应使用相同的规范化结果。颜色控件保留文本入口，不将旧链接限制为六位十六进制值。

单独访问 widget 时，可选参数非法则使用默认值；缺少必要参数则显示 widget 的错误状态。配置器保留无效草稿并显示问题，不用默认值覆盖用户输入的文本。无效字段暂用最近一次有效值预览，其他有效字段可以继续更新。存在字段问题时禁用复制，并标出原因。

生成地址使用当前站点 origin 和 `/<widget-name>`，不包含 `/config`。通过内置 `URL` 和 `URLSearchParams` 编码颜色、逗号、空格和中文。省略与默认值相同的参数；`humanize=true` 使用显式值。省略默认值意味着既有链接会跟随未来默认值变化，因此本次迁移保留现有默认值。

#### 5. 参数与默认值基线

所有 widget 引入公共 `bg` 和 `lang` 定义。`bg` 默认值为 `#ffffff,#191919`；`lang` 默认自动选择。widget 可覆盖公共定义的说明和默认值。

| widget            | 专属参数和现有默认值                                                                |
| ----------------- | ----------------------------------------------------------------------------------- |
| `year-progress`   | `primary=#37352f,#ffffffcf`；`secondary=#37352f29,#ffffff21`                        |
| `mini-calendar`   | `weekstart=0`；`primary=#37352f,#ffffffcf`；`secondary=#37352f6b,#ffffff47`         |
| `date-counter`    | `date=""`；`event=""`；`primary=#37352f,#ffffffcf`；`secondary=#37352fb2,#ffffffab` |
| `daytime-meter`   | `sun=#f59e0b`，只有一个颜色值                                                       |
| `repo-stargazers` | `repo=""`；`humanize=false`；`primary=""`；`star=#fbbf24,#d97706`                   |

仓库星标的空 `primary` 表示采用 widget 内置基础颜色。应保留这个语义，不能将空值当作非法布尔值。公共 CSS 基础色迁入各 widget 可用的局部样式规则，避免依赖配置器页面的文字色或背景色。

`meta` 包含中文名称、英文名称、简介、静态图标标识、SEO 标题和封面路径。`meta` 不导入 `.vue` 组件或表单 UI。首页使用静态图标，不实例化 widget。日期、仓库等输入使用 placeholder 提示，不把示例值写成默认值。

#### 6. 尺寸、样式、语言与更新

独立展示页提供全屏区域，配置器提供预览区域。两者的布局元素都声明 `container-type: size`，并提供不依赖 widget 内容的宽高。默认配置器预览比例沿用现有 `1200 / 630`；通过已知宽度和比例确定高度，必要时用绝对定位的内部元素建立查询容器。

widget 根元素接受 `class="size-full"`。多根节点、`ClientOnly` 或关闭属性继承的组件应把 `$attrs` 转发到实际内容根元素。不要同时保留内部的 `h-screen`。

内部布局优先使用百分比和 Flex/Grid；需要按区域缩放时，将 `vw`、`vh`、`vmin` 改为 `cqw`、`cqh`、`cqmin`。避免在 widget 内部意外建立更近的尺寸容器，改变单位的参照对象。[MDN 容器单位说明](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_queries#container_query_length_units)

widget 自定义 CSS 使用 scoped 或唯一命名空间。Tailwind 基础样式保留一份全局来源，不把 preflight 放进 scoped 样式。迁移时更新 `@source` 路径，并检查重复 CSS。

颜色拆分、背景和 CSS 变量使用响应式派生值。配置器更新同一个组件实例的 props，不把整个参数对象用作 `key`，不通过重新挂载刷新预览。仅切换 widget 类型时更换实例。

`lang`、翻译资源和翻译函数归属当前 widget 的响应式上下文。widget 使用公共 composable 建立自己的语言状态，不依赖应用级唯一资源。语言异步加载只提交最近一次选择的结果，避免快速切换时显示旧资源。

自动语言的服务端解析保留请求头策略。服务端在挂载根节点输出 `data-widget-lang`，值只允许已支持的语言标识。客户端 hydration 读取这个值，避免重新判断导致差异。配置器改变 widget 语言只影响预览内容，不改变整个配置器的语言和文档标题；切回自动时使用初始解析的语言。

使用当前日期或时间的 widget 保留现有客户端展示边界及更新频率。若某个 widget 的 SSR 时间或时区会产生不一致，则本体使用现有 `ClientOnly` 提供稳定占位。不要在模块顶层或服务端渲染期间启动计时器。

仓库参数改变后，延迟 300 ms 发起请求。新请求应取消或废弃旧请求；旧响应不能覆盖新仓库结果。颜色和 `humanize` 变化不触发重新请求。保留现有轮询周期和手动刷新行为，卸载时清理请求、计时器和轮询。界面缺少仓库时显示输入提示，不再从 `location.pathname` 拼接当前页面地址。

#### 7. 路由与构建

| 路径                    | 结果               |
| ----------------------- | ------------------ |
| `/`                     | 首页               |
| `/<已知-widget>`        | 通用 widget 展示页 |
| `/<已知-widget>/config` | 通用配置器页       |
| 未知 widget、额外路径段 | 404                |

路由解析完整匹配路径。末尾单个 `/` 归一化到对应路径；生成的地址不带末尾 `/`。客户端和服务端复用同一套匹配规则。`/api/*` 仍由 Nitro 的服务端路由处理。

本轮继续使用现有轻量路由，不添加 Vue Router。首页、配置器和不同 widget 之间使用普通链接导航。配置器内部的连续参数更新不触发页面导航。

注册表分别声明配置、组件及语言资源的加载器。首页可读取小型配置模块，但不执行 widget 组件加载器。独立展示页不导入参数表单组件。配置器按需加载目标 widget。[Vite glob 导入说明](https://vite.dev/guide/features.html#glob-import)

入口应按匹配结果加载页面及必要资源。移除将 widget 背景写到 `html` 的逻辑，背景改由 widget 自己设置。服务端 metadata 仍保持每个 widget 的标题、地址和封面。入口不要通过预加载列表重新提前加载所有页面；验收时同时检查浏览器网络和构建产物。

修改 `nitro.config.ts`，移除生产环境 `/` 的 Notion 重定向。保留现有 Workers preset。运行时代码只使用浏览器和 Workers 可用的 API，不新增 Node.js 专属依赖。

### Landing page 设计

静态设计稿见 [landing-design.svg](./landing-design.svg)，图片预览见 [landing-design.svg.png](./landing-design.svg.png)。设计稿包含桌面和手机布局，工具图标只是目录标识，不是 widget 实时预览。

#### 设计方向

首页像一页整理好的 Notion 工具目录。页面以 Silent Widgets 的品牌标题和直接说明开场；主体用图标、名称和一句用途描述帮助用户选择工具。用户点击“配置”进入对应配置器。

首屏文案：

> Silent Widgets
>
> 给 Notion 页面添加日历、进度和计数。

提示块文案：选择小工具，调整参数，再把地址嵌入 Notion。

目录顺序采用本计划开头的五个 widget。操作名称统一为“配置”；配置器的复制操作统一为“复制地址”，成功反馈为“已复制”。

页尾用三个真实步骤说明用途：选择小工具；调整参数并复制地址；在 Notion 中添加嵌入块并粘贴地址。提供指向 [Notion 官方嵌入说明](https://www.notion.com/help/embed-and-connect-other-apps) 的文字链接。

### 配置器布局与交互

以当前 `app/pages/index/page.vue` 为布局依据：居中 `max-w-xl`、上方品牌与 widget 选择、简介、预览、预览右上角复制操作、下方参数表。不要将 landing page 设计套到配置器上。

1. 将现有布局迁入 `app/pages/configurator/page.vue`，保留当前结构和间距意图。
2. widget 选择器列出五个工具。切换工具后导航到新工具的 `/config`，按新工具的默认值初始化，不跨工具沿用专属参数。
3. 参数表保留参数名、说明和控件三部分。手机上说明和控件换行，避免横向滚动。
4. 文本与日期使用文本输入；日期可附加选择器，但保留已有合法日期字符串的输入能力。整数枚举用选择框，布尔值用开关，语言用选择框。
5. 颜色用色块和文本框编辑。双模式颜色提供浅色、深色两个值，允许深色沿用浅色。原生颜色输入只作为辅助，不覆盖带透明度或其他合法形式的文本值。
6. 初始化时读取配置器 URL 的查询参数。有效编辑通过 `history.replaceState` 更新当前配置器查询串；无效草稿不写入地址，不增加每次输入的浏览历史。
7. 复制操作始终生成独立展示页地址。复制成功后显示“已复制”；失败时显示可选择的完整地址和手动复制提示。
8. 复制图标具有可访问名称，成功提示使用非打断式状态播报。错误提示与对应输入建立关联。

普通参数更新即时反映到预览，不刷新页面。只有仓库请求执行前述防抖。配置器不新增登录、保存到账号、浏览器持久化草稿、主题切换器或尺寸编辑器。

### 兼容性与处置

- 本轮保留旧 widget 路径、已使用的参数名、颜色默认值、自动语言策略和有效布尔开关写法。可选参数的非法输入使用默认值，避免现有解析错误导致页面崩溃。
- 迁移日期参数时不改变日期计数算法和时区语义，避免把结构重构扩展成行为变更。
- 首页只能在配置器布局迁出后替换。迁移完成前保留旧页面包装，避免中间状态失去可访问入口。
- 用户已有修改以工作区现状为基线。不得重置工作区，也不自动创建提交。
- 说明信息进入 widget 配置模块是本轮接受的取舍；配置器 UI 依赖进入 widget 页面不属于接受范围。
- 配置器与 widget 同页渲染后，优先排查未限定作用域的样式、全局 CSS 变量、静态 i18n 和组件重新挂载，不用 iframe 隐藏这些问题。
